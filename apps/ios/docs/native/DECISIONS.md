# Decisions

Prepared 23 October 2026. Product choices below come from the supplied mission, not an independently chosen replacement stack.

| Decision | Reason and reference |
| --- | --- |
| iOS/iPadOS 26+, Swift 6 | Required by the port kit. No old-iOS compatibility paths. Xcode 26+ is needed for compilation. |
| UIKit application/scene delegates (coordinator superseded below) | UIKit owns windows, navigation and restoration; SwiftUI content is hosted using [UIHostingController](https://developer.apple.com/documentation/swiftui/uihostingcontroller). Follow [UISceneDelegate](https://developer.apple.com/documentation/uikit/uiscenedelegate) and [state restoration](https://developer.apple.com/documentation/uikit/restoring-your-app-s-state). |
| Observation + structured concurrency | A scene's UI model is MainActor-isolated. Persistence is actor-isolated; no Combine state graph. [Apple Observation](https://developer.apple.com/documentation/observation). |
| GRDB 7.11.1, exact pin | Selected by the supplied specification; the version was verified against the upstream release API. [Release](https://github.com/groue/GRDB.swift/releases/tag/v7.11.1), [tagged package manifest](https://github.com/groue/GRDB.swift/blob/v7.11.1/Package.swift). No other persistence framework. |
| DatabasePool + migrations | A shared journal serves independent windows; WAL readers and explicit transactions keep ownership clear. [GRDB documentation](https://github.com/groue/GRDB.swift/blob/v7.11.1/README.md#database-connections). |
| XcodeGen spec as project authority | Reproducible native target/test configuration without hand-authoring pbxproj identifiers on Linux. [Project specification](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md). Generate on macOS; project generation has not been run here. |
| macOS 26 CI image | The authored simulator workflow uses the supported `macos-26` runner label from the official [runner image inventory](https://github.com/actions/runner-images#available-images). The workflow has not run. |
| HTTPS `.ts.net` hub on standard Serve port | Conservative current connection scope; validation is not authentication. Custom domains, ports and loopback HTTP are not implemented. Preview origins will have a separate policy. |
| Native auth remains a required backend contract | No forged browser Origin/Serve headers, CLI token reuse or insecure fallback. Designed and built 24 October (below). |
| Replaceable native terminal | Selected 24 October after the prototype below; originally: SwiftTerm is a candidate, not a verified selection. Prove Unicode/ANSI, IME, modifiers, selection, paste, mouse, resize, independent viewers and reconnect on iOS 26 before adding the dependency. [SwiftTerm upstream](https://github.com/migueldeicaza/SwiftTerm). |
| Preserve one canonical audit and spec | ZIP members equal loose documents byte for byte. Import their contents once as root AUDIT/SPEC with a short local scope/provenance preface. Do not copy the archive or legacy path aliases. |

Do not treat documentation research as proof that this app compiles or behaves correctly. Record new non-obvious API choices and simulator/device evidence here during implementation.

## Scaffolding — 24 October 2026

| Decision | Reason and reference |
| --- | --- |
| Foundation-only Swift Package test harness | Compile the same protocol sources and tests on Linux/macOS without introducing an alternative persistence/UI stack or copying implementations. The iOS app remains generated by XcodeGen. [Swift Package Manager](https://www.swift.org/documentation/package-manager/). |
| Strict API 28 read projection | Source `web/api.ts` declares version 28. Require this version and stable uids rather than silently synthesizing compatibility identities from tmux addresses. History, presets and review DTOs are later slices. |
| Connection-local snapshot/patch reducer | The audited stream has no revision counter; top-level field replacement matches `server/core.ts`. Explicit null differs from an omitted patch field. Corrupt events invalidate state pending resync. |
| Bounded incremental SSE decoding | Follow [WHATWG event-stream interpretation](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation), with configurable limits and deliberate rejection of malformed UTF-8. No live transport/authentication is implied. |


## Implementation — 24 October 2026

| Decision | Reason and reference |
| --- | --- |
| Device-key enrollment instead of passkeys on `.ts.net` | Passkeys need Associated Domains, which iOS 14+ fetches through Apple's CDN; a private tailnet host is unreachable from it (only the developer "alternate mode" bypasses the CDN), and every user has their own hostname, so no single entitlement could list them. [Supporting associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains). Instead: a Secure Enclave P-256 key per device and host (`SecureEnclave.P256.Signing.PrivateKey`, `.userPresence` access control so each sign-in needs Face ID), enrolled with a one-time code from an already signed-in device, signing `ah-native-{enroll,login}-v1` messages over a fresh host challenge. Backend: `ah` branch `native/1-device-auth`. |
| Bearer sessions, no cookies | `URLSessionTransport` disables cookie storage, caching and redirects. Native writes send `Authorization: Bearer` + `X-AH`; the host accepts a missing Origin only for a native bearer with no Cookie header, so browser CSRF defenses stay intact. Revocation fails closed: any 401/4401 signs the account out everywhere. |
| APNs from the host, ES256 JWT over HTTP/2 | Token-based provider authentication ([Establishing a token-based connection to APNs](https://developer.apple.com/documentation/usernotifications/establishing-a-token-based-connection-to-apns)); the key file stays on the host (`config.apns`). Registrations belong to a native sign-in and vanish with it. Approve/Deny actions appear only for plain permission prompts, with `.authenticationRequired`. Backend: `ah` branch `native/2-apns`. |
| SwiftTerm 1.99.1 for the terminal | Validated against a real tmux session through the app's `TerminalConnection` on Linux (ANSI, wide glyphs, input, resize). Used through its public `TerminalView`/`TerminalViewDelegate` API; bracketed paste through `paste(_:)`. [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm). |
| iOS 26 `updateProperties()` instead of Combine | UIKit tracks Observation reads in `updateProperties()` and re-runs it on change ([updateProperties()](https://developer.apple.com/documentation/uikit/uiviewcontroller/updateproperties())); the shell follows `SceneModel` with no publishers. |
| `UITab`/`UITabBarController(tabs:)` in the split's `.compact` column | One `UISplitViewController` per window adapts between iPad sidebar+detail and iPhone tabs ([UISplitViewController.Column.compact](https://developer.apple.com/documentation/uikit/uisplitviewcontroller/column/compact)); both read the same `SceneModel`, so resizing never loses the place. |
| Menu-bar commands validated by key scope | `UIKeyCommand`s live in the main menu (discoverable with ⌘-hold, rebuilt when bindings change via `UIMenuSystem.main.setNeedsRebuild()`); `canPerformAction` disables any command whose chord the focused composer/terminal owns, so the key falls through to it. Field-edge commands get no menu chord. |
| One module for Linux and Apple | `Package.swift` compiles every non-UI source as `AgentHubKit` so models, keyboard routing and persistence run in `swift test` and against a disposable `ah` in `scripts/integration.sh`. |
| Sealed cache: HKDF(device secret, per-sign-in server key, origin) + AES-GCM | A stolen database alone reveals nothing; locking forgets the key; a revoked sign-in's server key is gone so old rows are unreadable; forgetting an account deletes its rows. The newest transcript page per session and the hub's session list are cached. |
| `agenthub://<host>/<route>` deep links | Same routes as push payloads (`<uid>`, `review/<stack>/<pr>`); only a uid-shaped path opens a session. No Universal Links (same Associated Domains limit as passkeys). |
| No fake progress or local "success" | Sends show `sending` until the host answers; refused sends return to the box; merges re-sync and stop if the head moved; "No checks reported" is shown as such, never as passing. |

## Keyboard-first workspace — 24 October 2026

Following the owner's [WORKSPACE-SPEC.md](../../WORKSPACE-SPEC.md).

| Decision | Reason and reference |
| --- | --- |
| Native commands beside the web's 89, not inside them | `CommandCatalog.web` stays the audited port (the parity check counts it); `CommandCatalog.native` adds split left/above, balance, swap, pane cycling, workspace next/previous, Go to session and focus-follows-pointer. Defaults avoid every web chord and each other (unit test), and the less common ones stay palette/pane-mode only rather than spending scarce chords. |
| One focus authority, keyed on what the window shows | The spec's "the pane that looks focused is the pane that receives input" fails when each view moves its own responder. `SceneModel.following` diffs route, layout, focused pane, workspace and zoom around every action and moves the keyboard once; responders report back through `didFocus`, which also moves the pane focus when you click into another pane's composer. |
| Keyboard follows only with a hardware keyboard | Making a `UITextView` first responder on touch alone raises the software keyboard over the content; `GCKeyboard` presence gates automatic moves, never explicit ones (Reply, Rename). [GCKeyboard](https://developer.apple.com/documentation/gamecontroller/gckeyboard). |
| Focus restored after transient UI by the window, not by UIKit | UIKit doesn't return first responder to a view under a dismissed presentation. The root tells the model when something is presented and when all of it is gone; requests made meanwhile are delivered after dismissal, otherwise the remembered responder is restored. |
| Hover focus is gated, not debounced | Pointer hover ([onContinuousHover](https://developer.apple.com/documentation/swiftui/view/oncontinuoushover(coordinatespace:perform:))) focuses a pane at once, like Hyprland's follow-mouse, except while dragging, under any overlay or scratchpad, in a submap or maximized, and for 0.35 s after the layout changes, so a pane sliding under a still pointer never steals the keyboard. On by default; a palette command turns it off. |
| Workspace next/previous visit occupied workspaces | Like Hyprland's `workspace e+1`: stepping skips empty ones when others are occupied, and falls back to the neighboring number when none are, so the command always does something visible. |
| Two-key chords are native, opt-in and at most two keys | VS Code-style "⌃K ⌃S" lets people bind more than the scarce single chords without stealing typing keys. Stored as an additive `then` on the web's chord JSON, so a binding blob stays readable. The first key must have ⌃/⌥/⌘; the second may be bare; Escape cancels; the window waits 2 s with a legend of what can follow. Menu key equivalents only ever carry single chords; hidden menu key commands catch each chord's first key, and a key command arriving mid-chord is treated as its second key. No default uses one. |
| Conflicts are scope-aware and resolvable | Two commands clash when their scopes overlap and their keys are equal or one is the other's first key. The editor offers to take the shortcut over (the other command keeps any other shortcut it has) instead of only refusing. Keys iPadOS keeps (⌘H, ⌘Space, ⌘Tab, screenshots, ⌘⌥D) or text editing needs (⌘C/V/X/Z/A, caret and word moves) are refused with the reason. |
| Recent palette rows only break ties | The spec asks for intelligent surfacing without unpredictability: an empty palette lists Recent first, but in search, recency only orders equally good matches, so typing the same thing always finds the same top result. |
| A session row runs on Enter and opens its choices on → | Go to session shouldn't need a submenu for the common case. Enter switches to it, or focuses its pane if it's already on screen, rather than replacing another pane and duplicating a viewer. → reveals Open as a new pane and Move to workspace N. Search never descends into these choices. |
| Pane menus live on the header, not the whole pane | A context menu on the whole pane would take long-press and secondary click from the transcript and terminal (copy, select). The header's split/pane button and its context menu carry the same `PaneMenuItems`, each focusing that pane and calling `perform`, so all four paths in WORKSPACE-SPEC §5 share one implementation. |
| Too small means one pane at a time, not a squeezed grid | Below 300×220 pt per pane the layout keeps its tree but shows the focused pane full size with a tab strip; directional focus, swap and the rest still work, and widening the window brings the split back exactly. |
| Solid floating surfaces | The palette, which-key and submap legends use the theme's surface with a hairline and shadow instead of `.regularMaterial`: the spec asks for depth without heavy translucency, and solid fills keep text legible over busy terminals. |
| The session list is painted from the sealed cache, never trusted | Once a sign-in has its cache key, `HubStore` shows last time's hub state (sealed every 10 s while live and on backgrounding) until the host answers, with a banner saying so. It is only for showing: restoration still waits for live state, peers wait for their own streams, and the first live snapshot replaces it entirely. `HubStateDTO` and `SessionDTO` became `Codable` (their keys already covered every field). |
| A content hit in an ended conversation opens its record, not a resume | The web resumes the session to show the matching turn. Natively an ended session's transcript reads without running anything, so a search result opens the record at that turn (older pages load until it's there) and Resume stays a deliberate choice. A live session opens on the GUI at the turn; a side-chat hit opens its Chat panel. |
| Handoff carries the web's hash, not app state | The activity holds only the host origin and the web app's hash for the place (`#<uid>`, `#<host>/<uid>`, `#review/<stack>/<pr>`), so the same activity opens the app on another device or, as `webpageURL`, the host's web app in a browser (https hosts only). A device not set up for that host says so instead of guessing. [NSUserActivity](https://developer.apple.com/documentation/foundation/nsuseractivity), set on the window scene. |

## Seeing it run — 25 October 2026

| Decision | Why |
| --- | --- |
| Mac app as Mac Catalyst at iPad scale | One target, the same UIKit/SwiftUI code, real Mac windows with the menu bar, pointer and system window tiling. "Optimize for Mac" would restyle every control and needs its own design pass; "Designed for iPad" can't be built and run without a signing team. |
| Debug-only `AH_EPHEMERAL`, `AH_DEBUG_PAIR`, `AH_SNAPSHOT_DIR` | A Mac build signed only to run locally has no keychain entitlement, and macOS won't load an ad-hoc test bundle into the UI-test runner. These let it run unattended for proof without writing secrets anywhere: everything stays in memory for one run. Never in release builds. |
| Demo agents run under ah's own Claude Code preset | `scripts/demo/host.mjs` puts a `claude` script on the host's PATH, so launch choices (models, efforts, permission modes) are the real ones and nothing in the app is special-cased for the demo. |
| Sessions and panes drag as their own content type | `dev.ealush.ah.native.session` (and `.group` for sidebar blocks), declared in Info.plist: a pane must not react to a file path or queued message dragged past it. |
| Resizing stops at the minimum pane size | Squeezing a pane below 300 × 220 pt tipped the whole window into one-pane-at-a-time; the model now knows the canvas and clamps. |

| Every backend capability has a native path; web parity isn't the goal | The owner's rule: nothing the ah server can do is unreachable from the app, and core ergonomics are a given, but web-only affordances aren't copied for their own sake. Coverage is audited from the server's routes, not from web components: the host's app launcher, rebuild and restart, and making API tokens moved from "host only" to Settings. The master password stays host-only because the server refuses it from anyone but the host. |
| Test and demo hosts never reach this machine's own ah or desktop | Restart would run `systemctl --user restart ah`, rebuild would build and restart it, and Omarchy's web-app installer would add a launcher to the real desktop. Both hosts override restart and rebuild and put stand-ins for the installer on their PATH that write into their own isolated data folder. |
| ⌘, opens the app's Settings | iPadOS otherwise sends ⌘, to the system Settings app's page for the app. The menu bar's Settings item is replaced, and ⌘, is a default binding for Settings everywhere, typing included. |
| The demo host plays GitHub and a model, and says so | Stack review needs pull requests and a model to brief them. The demo puts a stand-in `gh` on its PATH (pull requests in a JSON file, branches in a local bare repository as `origin`, merges and retargets changing both as GitHub would) and a scripted OpenAI-style endpoint as its default subscription. Every answer the scripted model writes says it's scripted, so no screenshot passes it off as a real review. |
| Apple's keys alongside ah's | ah's defaults are Ctrl-based (Omarchy's comfort) and stay. Each common action also gets the key iPad and Mac users reach for first: ⌘N new session, ⌘F search, ⌘. stop the turn, ⌃⌘S sidebar, ⌥⌘I side panel, ⌘[ / ⌘] previous and next session, ⌘D / ⇧⌘D split, ⌘/ shortcuts, ⌘, Settings. Menus show the ⌘ key where there is one. New Window moves to ⌥⌘N, as in Mail, because ⌘N makes the app's main thing. Every sheet closes with Esc and confirms with ⌘↵ (merges excepted: they can't be undone). Behind a sheet or the palette, keys reach only commands that work over a dialog, so a page never changes under an open sheet. |
| Agents show their own logos | ah's web draws each agent with its own artwork (vendored in `web/public/logos`, provenance in `web/logos.tsx`), and the native letter tiles read as placeholders beside it. `scripts/agent-logos.sh` rasterizes the same files into `Shared/AgentLogos.xcassets/Agents` (shared with the widgets, whose Live Activities show the same marks) at 2x and 3x; white single-color marks become template images so they're drawn in the theme's ink, app-icon logos fill their tile, and an agent added on a host without a known logo shows its initial in its `--c-<agent>` tint. The marks only identify the tool they stand for, as on the web. |
| Everything has a way in by touch | Keys and the palette are the fast path, never the only one. The iPad sidebar's More menu holds Settings, New Project, Worktrees, All Commands and (with a keyboard) Keyboard Shortcuts; a phone's Inbox has a Settings button and the same menu. The palette's "All Commands…" is the catch-all for everything else. |
| Siri, Shortcuts and quick actions read live and index nothing | App Intents (Open Session, What Needs Me, New Session, Send Message, Show Inbox, with App Shortcuts phrases for Siri, Spotlight and the Action button) run in the app's process against the hosts it's signed in to, and name sessions from the hubs in memory. Nothing is donated to Spotlight's index and no title goes into Home Screen quick actions, which the system keeps outside the app's sealed storage: the Inbox quick action carries only a count. Asking and sending answer in place and need the app's sign-in to still be valid; when it isn't they say to open the app. |
| A finished session takes a reply from its notification | ah's done alert carries category `AH_REPLY` (backend `native/2-apns`), shown with a text Reply action that requires the device unlocked. The reply goes to the session like any message (queued if the agent started again). If it can't be sent (ended, signed out), the session opens with the words in its composer. |
| Windows are named and can be torn off | Each window's title follows the session in front or the page (Stage Manager, the app switcher, the Mac's Window menu). A session's menu and the palette open it in a window of its own on iPad and Mac; the palette also has New Window. |
| Every control answers the pointer | System controls highlight under an iPad trackpad or mouse on their own; the app's custom ones (rows, chips, ask choices, transcript folds, panel buttons) are plain-styled buttons, which don't. Each gets the system highlight hover effect, so nothing clickable looks inert under the pointer. |
| A waiting agent's choices take the keyboard, safely | The answer panel holds the keyboard through a UIKit responder of its own (SwiftUI focus doesn't reach a plain view reliably on iPadOS), claimed for 1.5 s as the web's claimKeyboard does and yielding only to a text box or terminal someone chose. While it has the keyboard it keeps every key it understands, used or not: passed on, an arrow would move the system's focus to the sidebar and the next Space would act on whatever it reached, another session's permission prompt included. Nothing is highlighted until an arrow moves the cursor, so Space or Return right after a session opens never approves a prompt nobody read; digits pick directly. Each new set of choices registers its handler newest-wins, so the question just answered can't keep the keys while the next one shows. |
| The question dialog's review lists what you answered | Claude's AskUserQuestion ends on "Review your answers / Ready to submit your answers?". The app reads the question → answer pairs off it and shows them above Submit and Cancel, instead of hiding them behind "Show terminal text"; a hook still reporting the questions at that step doesn't bring the form back. A plan up for approval is named as a plan, and Claude's ExitPlanMode call is drawn as the plan (Markdown, open while it asks, one line once decided). |
| A terminal takes the keyboard on the first tap | SwiftTerm forwards a tap to a program that tracks the mouse (tmux, which ah's viewers run with mouse on) before it would focus, so on a phone the terminal never got the keyboard. A tap on a terminal without the keyboard now takes it; the next reaches the program as a click. SwiftTerm's own key row is off, so one row (the app's, as on the web) sits above the keyboard, with Hide Keyboard pinned at its end. |
| Signed by a Personal Team for now | The owner's free Personal Team signs device builds until there's a paid one. It can't sign Push Notifications or Time Sensitive Notifications (Xcode 27.1 refuses the provisioning profile, checked with a device build), so both entitlements are out and the app explains, in Settings → Notifications, that host alerts can't reach this build. Everything else (App Intents, quick actions, Secure Enclave keys, the Keychain) needs no capability. |
| The app alerts on its own when push can't | A build without push (signed by a Personal Team) or a device not registered with a host works out ah's alerts from the session lists it already follows (`AlertWatcher`, the host's own rules: needs you, finished after working, 30 s per session, nothing on the first look) and posts them shaped like the host's push, so taps, Approve/Deny, Reply and grouping behave the same. Only while no window is in front, and never alongside the host's push. Leaving the app with a session at work asks iOS for its usual background time to catch the reply. |
| Leaving the app stops looking | ah treats an open transcript stream or attached terminal as the device viewing the session, and a turn that finishes while someone views it is seen: no alert. Backgrounding now closes the session's stream and detaches its terminal (both resume on return), so leaving the app means not looking. |
| Notification Center stays honest | While the app is in front an alert goes to Notification Center only (the app's nudge says it) and not at all for the session on screen. A "needs you" alert leaves once its session stops waiting (answered anywhere; only a live list decides), and any alert leaves once its session is opened. Grouped alerts say how many more there are. The first, sealed-cache look at the session list at launch no longer nudges. |
| Long transcripts load, and say so when they can't | ah sends a transcript snapshot as one line of JSON, and a long session's (screenshots, long outputs) runs to megabytes; the transcript stream now takes up to 64 MiB a line (the session list 32 MiB), where 1 MiB refused it and the app retried forever on "Connecting to the transcript…". The wait between tries resets only once something is read, a part the app can't read becomes an unknown part instead of failing its entry, and three unreadable tries in a row say so, with the terminal at hand. The transcript's collection view lays a new copy out afresh, held where it was. |

## Product leap — 14 November 2026

| Decision | Why |
| --- | --- |
| Approve/Deny from a notification answers the prompt it showed | The host fingerprints what a session asks (`askId`); alerts carry it and an answer sends it back, so an old alert can't approve a newer command nobody read. The action waits for the host's answer under a background task, and a refusal posts a note instead of failing silently. A host that predates it ignores the field. |
| A share extension that reads the app's Keychain group, without an App Group | The sign-ins already live in the app's default Keychain group; naming it in both targets' `keychain-access-groups` shares them with no migration and no App ID capability. An App Group would add durable staging for offline shares at the cost of a capability the App ID doesn't have; until then the extension sends while it's open and says so when it can't. It never writes a sign-in (a 401 is the app's to handle). |
| The extension compiles the app's own client, not a copy | `Sources/Networking`, `NativeAuth`, `FeedSchema` and `Sources/Domain` (less three files that reach into Models) compile on their own, so the extension speaks to the host exactly as the app does, with no persistence or UI dragged in. |
| Continuations are the host's | The app asks the host for a plan, shows it, starts it with one idempotency key per sheet and follows the operation; it keeps no transcript of its own. Its words never claim more than the strategy carries ("doesn't get Claude Code's memory or reasoning"). A host without `features.portable` gets the text hand-off, labeled as one. |
| Lists show the last message, not the last tool | The owner's ask from the Inbox. The host reads the last thing said from the transcript's tail when it grows (`reply`), and the row shows it as a chat list would. |
| Live Activities at most three at once | More would crowd the Lock Screen; a finished one gives way first, then the oldest. Progress is never a percentage the agent didn't report: the queue behind the turn is counted instead. |
| The keyboard has one owner: UIKit's keyboard layout guide | The conversation's composer stands on `view.keyboardLayoutGuide` in a UIKit container (`ConversationController`). The terminal, an iPad side panel, a pane's chooser and the scratchpad use `AboveKeyboard`. Every hosting controller in a session screen leaves the keyboard out of SwiftUI's safe area (`safeAreaRegions`). There was a notification-driven tracker as well as SwiftUI's own avoidance. Between them the bar's distance from the keyboard moved with its content: measured on main, 17 pt off at six lines, 31 pt with two pictures, 87 pt after cancelling a queued message. Apple calls the guide the recommended approach (WWDC23 "Keep up with the keyboard"): it follows interactive dismissal, the hardware keyboard's bar, Split View and Stage Manager. SwiftUI's keyboard avoidance isn't documented to do those. See [CONVERSATION-LAYOUT.md](CONVERSATION-LAYOUT.md). |
| One transcript, on a collection view | The SwiftUI ScrollView over a LazyVStack estimated its rows' heights. To stay at the end of a long, streaming turn it needed three default scroll anchors, rebuilds and eight delayed scrolls, and it still came to rest past the end with nothing drawn. The collection view lays out measured rows, and one anchor decides where it sits, so it's the only transcript now. |
| The queue keeps to its share | The queue tray takes at most 45% of the conversation's room and scrolls inside it. The transcript keeps 120 pt beside the box. In a tight room the queue folds to its line, then gives way to the box. The room comes from the keyboard guide and the safe area only, never from the dock, so the queue can't size itself: on main, its cap came from a height it changed itself, and opening or folding a long queue with the keyboard up stalled the main thread for 30 s. |
| Notes are sessions by key, not fake sessions | A scratchpad is addressed as `note:<uuid>` everywhere a session key goes (routes, panes, the journal, the palette, the switcher), so it opens, tiles, restores and switches like a session. It never parses as a `SessionKey`, `SceneModel.session(_:)` returns nil for it, and nothing asks a host about it: no process id, agent state, queue or tmux window is invented. Views branch on the key (`NoteScreen`). |
| A note's text is plain in GRDB | Unlike host state (the sealed cache, readable only with a sign-in's key), a note is the person's own writing and must open with no sign-in and no network. It lives in the `note` table under the database's Data Protection. A forgotten account's notes stay on the device, unsynced. |
| Notes sync by revision; nothing is merged | Each write names the host revision it was made on and keeps its write id across retries (`docs/spec/15-scratchpads.md`). Changed apart, both versions are kept until the person chooses (Keep Both, Keep This Device's, Keep the Other). Edits that meet a deletion elsewhere are kept as a new note. No CRDT. |
| Hand-offs never claim more than the host said | Send to Agent goes through the host's send (queued while busy, resumed when ended) under an id kept before it goes, so Try Again asks the host what happened instead of sending twice. Offline nothing is sent; an unanswered request is "not sure it arrived". Put in a Session's Box asks before it combines with a draft there. |
| Saving as a file is a snapshot | Save as File writes a copy into a project through the host's export (inside the project and the browsable roots, never over a file unless asked). The note stays the original; no file is watched or synced back. |

## What agents make, as it's meant to be seen — 26 November 2026

| Decision | Why |
| --- | --- |
| A Markdown file reads as a page | Quick Look shows Markdown as plain text: an agent's review lost its pictures, tables and the evidence beside it. The app's own Markdown view draws it (`MarkdownDocumentSheet`), with its relative links and pictures resolved against its folder as GitHub does, and Show Source a tap away. |
| Mermaid is drawn by Mermaid itself, offline | Agents write diagrams as ```mermaid fences, and no native renderer reads Mermaid's grammar. The app bundles `mermaid.min.js` from npm `mermaid@12.3.0` (published 3 November 2026; tarball sha1 `e860165e0a19778ebef98038c0436bbee6783ba9`, file sha256 `336df803d87a38b70a01e736e666c8f7601d2ce42f5e47c8fafe5d721074b9a3`), MIT, its licence beside it (`App/Mermaid/mermaid-MIT.txt`). It runs on a hidden page that can load nothing (see ARCHITECTURE.md), and each diagram is shown as a picture taken of it, so the transcript holds no web views. A diagram Mermaid can't read stays its code, with Mermaid's reason. Update it by replacing the file and these hashes, never from a CDN at run time. |
