## Nonnegotiable technology decisions

1. **Minimum deployment: iOS 26.0; iPhone and iPad**, including Stage Manager/multitasking, external pointer and hardware keyboard. No earlier-iOS compatibility shims.
2. **UIKit owns the application shell and navigation**: application/scene lifecycle, window scenes, root navigation, tab/sidebar/split containers, controller presentation, adaptive routing, focus/key command routing, and state restoration. Use scene delegates and UIKit navigation coordinators rather than making a SwiftUI `App` and `NavigationStack` the app shell.
3. **SwiftUI provides the actual content of each feature view controller**, embedded in UIKit through `UIHostingController`/child-hosting controllers. An individual SwiftUI content screen may embed specialized UIKit views (`UIViewRepresentable`) where needed—especially the terminal, advanced code editor/diff or native browser preview. No React shell or wholesale WKWebView rewrite. `WKWebView` is appropriate only for inherently web content, such as a running development-server preview.
4. **Observation framework, never Combine for app state.** Use `@Observable`, `@State`, environment injection and modern Swift concurrency. No `ObservableObject`, `@Published`, `@StateObject`, Combine publishers, or accidental duplicate sources of truth. Prefer actors, `async/await`, `AsyncSequence`, explicit cancellation and `@MainActor` UI boundaries.
5. **GRDB.swift is the selected local persistence library**—not SQLiteData, SwiftData, Core Data or a custom SQLite wrapper. Rationale: SQLiteData itself sits on GRDB and supplies a higher-level structured query, observation and optional CloudKit layer. The client needs explicit transactional persistence, migrations, predictable WAL-backed readers/writer concurrency and a small, auditable offline cache/restoration journal; there is no reason to adopt CloudKit or more state machinery. Use a `DatabasePool` where justified, migrations, indices, scoped transactions, and testable repositories. Do not turn local cache into a second authority for server-owned state.
6. **Native Apple design and behavior**: Apple's current Human Interface Guidelines, current UIKit/SwiftUI API documentation, and relevant WWDC session transcripts are the primary references. When uncertain, research before implementing: official docs first, then Apple's documentation mirror/source or WWDC transcripts. Older talks may be outdated—verify against the iOS 26 SDK. Record non-obvious design/API decisions with links in `docs/native/DECISIONS.md`. Do not invent API symbols or infer support from blog posts.
7. **State restoration is fundamental, not a follow-up.** The app should return to the same scene, screen, stack/PR, session, pane/workspace layout, selected tab, scroll position and draft context after process termination, subject to revoked sessions/deleted resources. Use UIKit scene restoration (`UISceneDelegate` / `NSUserActivity` / `UISceneSession` restoration activity) **and** proactively save a versioned `SceneSnapshot` in GRDB on significant navigation/layout changes and backgrounding; do not depend on a last-second termination callback. For multiple iPad windows, persist state per `UISceneSession.persistentIdentifier`. Restoration must reconnect to server truth, not resurrect obsolete live process state. Keychain holds secrets; restoration snapshots must not contain auth tokens or raw sensitive drafts.
8. **No destructive migration.** Keep the Linux/Omarchy Node/tmux/SQLite backend, CLI, and working web client intact. The iPhone/iPad app is another client of the same server and shares its conversations, queues, drafts, review state, and device presence.

## Native client architecture and server boundaries

- Define **versioned, typed DTOs** for `web/api.ts`, `web/reviewApi.ts`, `server/feed/schema.ts`, session state patches, queue operations, review data and file APIs. Avoid hand-written untyped dictionaries scattered through views. Maintain a parity map of request/response behaviors and errors.
- Transport layer: `URLSession` REST, reconnecting SSE client (full initial state + patches, wake resync, polling fallback), WebSocket PTY (binary/control/resize protocol), authenticated file upload and streaming downloads. Use actors and clearly-owned tasks; preserve error visibility and retry/idempotency boundaries. State in SwiftUI views is a projection of server truth plus deliberately local transient state.
- **Security is a prerequisite to app functionality.** Read `server/gate.ts`, `server/auth.ts`, `SECURITY.md` and tests. Current Host/Origin/`X-AH`/Tailscale Serve model is browser-centric and must not be bypassed using forged `Origin` or `Tailscale-User-*` headers. Design a **separate, explicitly authenticated native-client contract** with scoped/revocable per-device credentials, legitimate host identity and pairing, correct native HTTP and WebSocket authorization, CSRF defenses preserved for browsers, tight trust boundaries, secure Keychain storage, fail-closed revocation, and server-side audit events. Research native passkeys/Associated Domains for a private `.ts.net` host; if the webcredentials association cannot be supported, implement a properly authenticated native pairing alternative instead of disabling checks. No public tunnel, Funnel, insecure HTTP or widened bind address. Document manual signing/entitlement requirements rather than pretending they are configured.
- Push: iOS app registers with APNs, host sends through Apple's APNs service, device token lifecycle and revocation are managed; notification content is privacy-minimized and routes to stable session identity. A suspended app is NOT assumed to maintain live SSE.
- Developer preview: `WKWebView` only for preview pages, with an explicit authenticated proxy/cookie/origin strategy and isolation from the hub; verify HMR and hardcoded absolute URLs. Never expose raw dev ports to the public internet.
- Persistence: GRDB stores versioned scene snapshots, lightweight cache metadata, transcript page caches if justified, id mapping, navigation and offline pending UI state. Encrypt sensitive cached content using CryptoKit keys from Keychain or a demonstrably equivalent protected scheme; GRDB/SQLite by itself does not encrypt data. Use iOS Data Protection, bounded cache retention, account-bound invalidation and cleanup on signout/revocation. Never persist API keys in preferences/logs.
- Multiple windows/scenes must not fight over local navigation state, while shared server state updates all scenes. Make ownership clear: host-global vs per-device vs per-window/scene.
