| P1 | Keyboard on real hardware | All 89 commands route through tested `SceneModel` logic; the `UIKeyCommand` mapping, `canPerformAction` deferral to text/terminal, Colemak/physical-key handling and system-shortcut conflicts need an iPad with a hardware keyboard. |
| P1 | Review confidence | Exact-head merge re-syncs and refuses a moved head; approving now sends the head of the revision shown, and a host on `ah` `review/1-approve-head` refuses an approval for any other (older hosts approve the current one); "No checks reported" is never treated as passing; nothing is marked reviewed for you (the architecture view and briefings never do). Still needs a disposable GitHub stack fixture end to end. |
| P2 | Preview isolation | Non-persistent `WKWebView` with a host-only preview cookie; HMR/WebSocket behavior through the proxy needs a device check. |
| P2 | Release packaging | App icon, privacy manifest review, App Store metadata and distribution signing. |
| P2 | Live Activities with the app put away | A session's Live Activity is moved by the app while it runs, and by the host's liveactivity push (`ah` `live/1-activity-push`) once the app is put away. A push-token activity needs the Push Notifications entitlement; without it (today's builds) the app starts a local one, which nothing moves while the app is put away: after 10 minutes it shows as out of date ("Open Agent Hub to see where it is", Approve/Deny hidden) until the app comes back. A peer host's sessions are only ever moved by the app (the hub follows its own windows). The host sends no stale date of its own, so a host that goes offline leaves a pushed activity looking current until its 8 hours are up. |
| P2 | Share extension | Built (PL-13) on a Keychain access group (the app's own identifier), which every provisioning profile allows, so it needs no App ID capability; the extension's App ID (`dev.ealush.ah.native.share`) has to be registered by the first signed build (Xcode's automatic signing or Xcode Cloud). Not verified: a signed device build, the Keychain group on a device, TestFlight's validation of the embedded extension. What it can't do: keep a share for later when the host can't be reached (that needs an App Group and a background upload session); offline, it says so and nothing is sent. |
| P2 | Siri on a device | The App Intents build and their logic is unit tested, but no phrase has been spoken to Siri on a device yet; App Shortcuts registration is only visible on a signed install. |
| P2 | ⌘, on iPadOS 26 | The system takes ⌘, for its own "app settings" command and opens the Settings app's page for Agent Hub, even with the app menu's Settings item replaced (seen on the iPad simulator, 10 November 2026). The menu bar's "Settings…" and ⌃⇧3 open the app's own Settings. |
| P2 | A host that goes quiet | A host that stops answering without closing the connection (its Mac asleep, a network that drops packets) shows its last state as live until the stream's idle timeout (40 s; the host pings every 25 s) and a poll's timeout have run out: about a minute, then the Offline banner with Retry (seen on the simulator with the demo host stopped, 10 November 2026; it was a minute and a half at a 60 s idle timeout). |
| P1 | Videos over 50 MB | The app streams a picked video from disk, but the host's `/api/upload` reads the whole body into memory with a 50 MB cap (`UPLOAD_LIMIT` in `ah` `server/main.ts`), so a longer video fails to attach ("Couldn’t attach…"); `aVideoAttachesFromDiskWellPastTheOldLimitAndLeavesNoFile` (51 MB) fails for that reason. Needs an `ah` change that streams uploads to disk under a higher cap, on its own branch. |
