# One repository — 21 November 2026

The native app (formerly `ealush/ah-native`) now lives in this repository at `apps/ios`,
with its whole history. The server, web client and CLI moved from the root to
`apps/server`. Nothing the product does changed.

## Updating an existing install

```bash
cd ~/code/ah
git pull
pnpm build                      # links dependencies for the new layout first, then builds the page
systemctl --user restart ah     # or Settings → System → Rebuild and restart
```

Restarting without the build works too: `node bin/ah.js serve` builds the page once when
`apps/server/dist` has none. Settings → System → Rebuild works for this update as well. A server still running the old layout
removes its `dist/` and runs `pnpm build` at the root, which now links the workspace's
dependencies before building `apps/server/dist`, then restarts into the new layout.

What stays the same:

- **The systemd units.** `node bin/ah.js serve` from the repository root keeps working:
  the root `bin/ah.js` imports `apps/server/bin/ah.js`. The installed `~/.config/systemd/user`
  copies need no change; `apps/server/contrib` holds the same units for new installs.
- **Agent hooks.** Hooks written by `ah hooks install` name the root `bin/ah-hook.js` by
  absolute path, and it runs the real hook. `ah hooks install` again points Claude Code's at
  `apps/server/bin/ah-hook.js`; Codex's notify line is left as it is (it already runs an
  `ah-hook.js`), so keep the root `bin/ah-hook.js`.
- **State.** `~/.local/state/ah` (the SQLite database, registry, tokens), `~/.config/ah`,
  uploads and the tmux server (`ah-tmux.service`) are where they were. Their paths never
  depended on the source location.
- **`pnpm link --global`.** The root package still names `bin/ah.js` as `ah`.
- **mise.** The new root `mise.toml` parses without `mise trust` (no templates, no tool
  options), so the unit's node shim still resolves the installed Node 26 from this checkout.
  Run `mise trust` yourself only to use `mise run …` here.

Left behind and safe to delete: the root `dist/` from before the move (the page is now
served from `apps/server/dist`).

## For the native app

- The App Store Connect app, bundle IDs, signing team, entitlements and Keychain groups are
  unchanged.
- **Xcode Cloud still builds `ealush/ah-native`.** Until its workflows are pointed at this
  repository (project `apps/ios/AgentHubNative.xcodeproj`, generated by
  `apps/ios/ci_scripts/ci_post_clone.sh`, which stays beside it as Xcode Cloud requires),
  TestFlight builds come from the old repository. That's a change in App Store Connect,
  not in this repository.
- `ealush/ah-native` stays as it is (not archived); new native work lands here.

## Verification

See the pull requests of this stack: each layer lists the checks it ran. An existing install
was rehearsed end to end in a throwaway clone with its own state, tmux server and port: the
old layout installed, built, served and its hooks installed; then the new layout checked out,
the old Rebuild path run, the server restarted through the root `bin/ah.js` (page and API
answered, the database untouched), and a hook at its old absolute path still set the
session's state.
